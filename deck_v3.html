# AI 도구에서 MCP 도구 호출

  "results": [{ "규정명": "…겸직 지침",
  "조문번호": "제○조", "record_id": "rule-…",

이게 확산의 핵심

  • 입시 챗봇(발전계획 동일 항목)이 같은 서버를 재사용
  • 차세대 아르샘·간편행정의 규정 근거 엔진으로 연결
  • 규정이 개정되면 서버 한 곳만 갱신 → 전 응용에 반영

→ 관련성 게이트를 코드로: 일반어 분리 + 핵심어 최소 매칭 + 회귀 테스트로 고정.

배운 것 — 신뢰성은 프롬프트 문구가 아니라 검증 가능한 코드와 테스트로 강제해야 성립. 프롬프트 설계 → 적대적 검증 → 재설계의 반복, 이것이 이 시스템의 실제 개발 과정.

프롬프트 3종(역할·수집·자기점검) + 다른 AI 모델의 적대적 감사(HIGH 6건)로 반복 개선

확산 논리 — 챗봇은 응용 하나일 뿐. 규정을 표준화한 인프라가 남으면, 다음 과제는 데이터를 다시 모을 필요 없음.
