왜 챗봇이 아니라 MCP인가

규정을 한 번 정규화하면, 특정 챗봇 하나에 갇히지 않고 어떤 AI 도구에서든 같은 규정 근거를 꽂아 쓸 수 있다. 입시 챗봇·차세대 아르샘 등 후속 응용이 같은 배관을 재사용한다.

신뢰성 설계 (핵심)

답변은 조문 원문 + 규정명 + 출처 URL을 반드시 인용한다. 근거를 못 찾으면 지어내지 않고 "해당 규정 미확인"으로 답한다 — 규정 안내에서 할루시네이션은 곧 잘못된 규정 안내이기 때문.

현재 시제(試製): 핵심 편제 37개 규정 · 866개 조문 인덱싱 완료

직접 효과

  • 규정 접근성: 자연어로 즉시 조문·출처 확인
  • 반복 문의 경감: 담당자 부하 완화
  • 감사 예방: 업무 전 자기점검으로 지적 유형 사전 차단

확산 가능성

  • 같은 MCP 인프라로 입시 챗봇(11.2.2 동일 항목) 재사용
  • 차세대 아르샘·간편행정 근거 엔진으로 연결
  • 규정 개정 시 동기화 한 번이면 전 응용에 반영

확산 논리 — 챗봇은 응용 하나일 뿐이다. 규정을 근거로 표준화한 인프라가 남으면, 다음 과제는 데이터를 다시 모으지 않고 배관만 꽂으면 된다.

정량 절감효과는 본부 시범 운영 데이터로 측정 예정(현재는 접근성·자동화 개선에 한정)

할루시네이션 차단

관련성이 낮으면 조문을 억지로 붙이지 않고 "미확인"으로 응답. 무관 질의 차단을 회귀 테스트로 고정.

규정 개정 동기화

규정 원본 갱신 시 현행본만 인덱싱, 개정 전 버전은 구분. 출처 URL로 원문 대조 가능.

감사 자료 민감성

감사 지적을 유형으로만 익명화해 자기점검에 사용. 특정 부서·개인·사건·금액은 담지 않음.

협력 구도

정보화본부(규정 챗봇 담당) · 청렴센터(자기점검 자료) 연계. 규정 안내는 참고이며 공식 해석·감사 판단을 대신하지 않음을 명시.
