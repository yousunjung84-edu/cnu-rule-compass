# cnu-rule-answer

> **스킬 v1.3.0 · 기준 서버 버전: cnu-rule-compass v1.4.0** (2026-08-10).
> 이 문서의 도구 계약·동작 기술은 그 버전 관측이다. `get_corpus_stats`로 현재 상태를
> 확인할 수 있다. v1.0.0에서 관측되던 색인 누락·다중어 질의 축소·꼬리 절 제목 오탐은
> 서버에서 수정되어 이 문서에서 제거했다.

## 1. 목적

`cnu-rule-compass` MCP로 전남대학교 규정·지침을 조회해 문의에 답할 때,
**(a) 근거 조문 병기, (b) 판본 검증, (c) 무날조(no-fabrication)** 를 강제한다.

이 스킬이 지키려는 것은 답변의 유창함이 아니라 **답변의 추적가능성**이다.
사용자가 답변을 들고 학사과에 가서 "이 조문 맞습니까?"라고 물었을 때
그대로 확인되어야 한다. 이 기준을 통과하지 못하는 문장은 쓰지 않는다.

## 2. 절대 원칙 (위반 시 응답 폐기)

1. **도구가 반환하지 않은 내용은 쓰지 않는다.** 기억·추정·일반 대학 관행·타 대학 사례로 빈칸을 메우지 않는다.
2. **조문을 요약해서 근거로 삼지 않는다.** 원문을 인용하고, 해석은 원문과 시각적으로 분리한다.
3. **인접 조문을 근거로 승격시키지 않는다.** 질의 주제와 조문 주제가 다르면 "근거 없음"이지 "유사 근거 있음"이 아니다. (→ §6)
4. **못 찾으면 못 찾았다고 쓴다.** `status: "not_found"`이거나 관련성 심사를 통과한 결과가 0건이면 §7-B 템플릿을 그대로 쓴다.
5. **판본을 확인하지 않은 조문은 인용하지 않는다.** (→ §5-A)

## 3. 도구 시그니처

| 도구 | 파라미터 | 용도 |
|---|---|---|
| `search_rule` | `query: string`, `k?: int (기본 5)`, `include_superseded?: bool (기본 false)`, `include_repealed?: bool (기본 false)` | 자연어 → 후보 조문. 진입점 |
| `get_article` | `rule_name: string`, `article_no: string`, `record_id?: string` | 규정명+조문번호로 단일 확정 조회 |
| `get_article_as_of` | `rule_name: string`, `date: string`, `keyword?: string` | 특정 시점 유효 판본 (개정 계열 수집 규정 한정) |
| `get_related_articles` | `record_id: string`, `direction?: "outbound"\|"inbound"\|"both"`, `resolve?: bool` | 상호참조 추적. 인용하는/인용받는 조문 |
| `list_rules` | `division?: string`, `include_superseded?: bool` | 수록 규정 목록(편제·계층·조문 수·수집일시) |
| `get_corpus_stats` | — | 코퍼스 규모·편제 분포·색인 정합성 |

응답 최상위 `status`는 `ok` 또는 `not_found`. `count: 0`이면 검색 실패다.

### 조문 레코드의 주요 필드

`규정명` `편제` `조문번호` `조문제목` `본문` `장` `절` `source_key` `source_url`
`수집일시` `record_type` `revision` `record_id` `score` `matched_terms` `routing`
`is_current` `superseded_by` `is_repealed` `repealed_date` `repealed_clauses` `repealed_items` `text_integrity`

### `hints` — 결과가 0~1건일 때만 붙는다

```json
"hints": {
  "query_terms_unmatched": ["생성형", "챗봇"],
  "suggest": "no_such_concept" | "cross_reference",
  "note": "..."
}
```

`query_terms_unmatched`는 **코퍼스 어휘집에 아예 없는 질의어**다.
이 필드가 "검색 실패"와 "코퍼스에 개념 자체가 없음"을 구별해 준다. (→ §6-2)

## 4. 표준 절차

```
1) search_rule           → 후보 확보 (k=8 이상 권장)
2) 관련성 심사           → §5-B. 여기서 대부분 탈락시킨다
2.5) 상호참조 추적       → §5-C. get_related_articles 한 번
3) 판본 심사             → §5-A. is_current / is_repealed 필드로 판정
4) get_article           → 인용할 조문을 규정명+조문번호로 재확인 (권장)
5) get_article_as_of     → 과거 시점 기준 질의일 때만
6) 응답 조립             → §7 템플릿 + §8 체크리스트
```

**2)와 2.5)를 건너뛰지 않는다.** 이 스킬의 가치는 대부분 여기에 있다.
`search_rule` 결과를 그대로 옮기는 것은 스킬 없이도 할 수 있는 일이다.

자연어 문장으로 물어도 된다. v1.1.0에서 다중어 질의가 결과를 줄이지 않도록 고쳐졌고,
`재입학`·`재입학 허가 신청`·`재입학 어떻게 하나요`가 모두 같은 정답 조문을 포함한다.
다만 **사용자의 구어체는 규정 용어로 바꾸는 편이 여전히 낫다**
(`references/corpus-map.md` §4 변환표). 코퍼스에 없는 어휘는 동의어로 확장되지 않는다 —
예: `이의신청`은 코퍼스가 `정정`으로 쓰므로 그대로 치면 순위가 밀린다.

## 5. 검색과 결과 심사

### A. 판본 심사 — 필드로 판정한다

규정명 괄호를 눈으로 보고 추정하지 않는다. 서버가 필드로 알려준다.

| 필드 | 뜻 |
|---|---|
| `is_current: false` | 구판본. 같은 이름의 현행 규정이 따로 있다 |
| `superseded_by` | 대체하는 현행 레코드의 `record_id` |
| `is_repealed: true` | 조문 자체가 삭제됨 |
| `repealed_date` | 삭제일 (`YYYY-MM-DD`, 원문에 없으면 null) |

**기본 검색은 현행·유효 조문만 반환한다.** 구판본·삭제 조문을 보려면
`include_superseded=true` / `include_repealed=true`로 명시적으로 켠다.

- 감사 대응처럼 "그 업무 당시 규정"이 필요하면 `get_article_as_of`를 먼저 고려한다.
- 옵션을 켜서 구판본을 인용할 때는 **반드시 `is_current: false`임을 답변에 밝힌다.**
- 신·구 판본의 본문이 다르고 어느 시점 기준인지 불분명하면, 임의로 고르지 말고
  두 판본을 모두 제시하고 사용자에게 확인받는다.

### A-2. 원문 문자 손상 — `text_integrity`

일부 조문 본문에 가운뎃점·원문자·인용부호가 `?`로 저장돼 있다
(예: 학칙 제25조 `입학(편?재입학 포함)`). **정본 제공처(law.go.kr) 응답 자체의 손상**이라
재수집으로 고쳐지지 않고, 무엇이었는지 추정 복원하는 것은 날조다.

서버가 `text_integrity` 필드로 알려준다(손상 없으면 `null`).

```json
"text_integrity": {"suspect_marks": 1, "kinds": ["가운뎃점_추정"], "sentence_questions": 0, "note": "..."}
```

이 필드가 붙은 조문을 인용할 때:

1. **본문을 원문 그대로 옮긴다.** `편?재입학`을 `편·재입학`으로 고쳐 쓰지 않는다.
2. 인용 아래에 한 줄 덧붙인다 — "※ 원문 표기에 문자 손상이 있습니다(정본 제공처 기준).
   정확한 표기는 원문 링크에서 확인하시기 바랍니다."
3. 손상 문자가 의미를 가르는 자리면(예: 열거인지 범위인지) **단정하지 말고** 원문 확인을 안내한다.

현재 규모: 54개 조문 / 125자 (전부 규정 계층). `get_corpus_stats`의 `문자손상_조문_수`로 확인한다.

#### 손상이 아닌 것 — 옛 표기는 고치지 않는다

`text_integrity`가 붙지 않았는데 어색해 보이는 표기가 있다. **그건 손상이 아니라 원문 표기다.**

| 표기 | 판정 |
|---|---|
| `다음 각호1에 해당하는` / `다음 각 호 1에` | **원문 그대로.** 표준 문언 `각 호의 1`에서 `의`를 생략한 옛 표기다. 학칙 제30조는 정본 응답에, 옛 강사료 지급지침은 HWP 원문 단계에 이미 그렇게 있다(2026-08-10 3축 대조). 전체 83건 중 18건이 이 형태이고 나머지 65건은 `각 호의 1`이다 |
| `각 1부`, `각 1학점` | 정상. '각각 1부/1학점'이라는 뜻이다 |

의미가 달라지지 않으므로 `text_integrity`로 표시하지 않는다.
**인용할 때 `각 호의 1`로 고쳐 쓰지 않는다** — 오타처럼 보여도 원문이다.

### B. 관련성 심사 — 키워드 오탐은 여전히 온다

`search_rule`은 점수 기반이라 **주제가 달라도 단어가 겹치면 상위에 올라온다.**
점수 순위를 신뢰하지 말고 아래 순서로 본다.

1. **`조문제목`** — 가장 강한 신호다. 제목이 질의 주제와 일치하면 본문 점수가 낮아도 채택 후보다.
2. **`matched_terms`** — 질의의 **핵심어**가 매칭됐는가. 부수어만 매칭됐으면 탈락이다.
3. **`장`·`절`** — 조문이 속한 편제 구조. 학적변동 문의인데 `절`이 `제3절 휴학`이면 맥락이 맞는다.
4. **`편제`** — 아래 차단 규칙에만 쓴다.

#### 편제는 차단에만 쓴다 (허용목록을 만들지 않는다)

"이 문의에는 이 편제만 맞다"는 식의 허용목록은 **정상 조문을 탈락시킨다.**
실제로 학사 문의의 근거가 `규정집/학칙 및 학위수여`, `규정집/교무행정`, `학사과`에
동시에 걸쳐 있고, 정보보안 사안은 `정보화본부`에 있다. 편제는 예측 가능한 축이 아니다.

대신 **명확히 무관한 것만 차단한다.**

| 차단 대상 | 이유 |
|---|---|
| `전남대학교 사범대학부설고등학교학칙` | 부설고교 규정. 대학 학사 문의 근거가 될 수 없다. "퇴학", "재입학", "자퇴"에서 상시 오탐 |
| `총장임용후보자 선정...` 계열 | 선거 절차. "이의신청", "정정", "기간"에서 오탐 |

그 밖의 편제는 **탈락시키지 말고 후보로 남긴다.** 조문제목으로 판정한다.

**대학원생 문의는 소속 대학원의 교학규정을 반드시 확인한다.** 일반대학원·교육대학원·
법학전문대학원·정책대학원·농생명산업대학원·글로컬미래전략대학원의 교학규정이 각각
별도로 존재하고 내용이 다르다. 학부 기준 조문을 대학원생에게 적용하지 않는다.

### C. 상호참조 추적 — 도구 한 번으로 끝낸다

규정 본문은 상위 규정을 조문번호까지 지목해 인용한다. 이 사슬을 따라가면
그 사안의 **중심 조문**에 닿는다. 손으로 정규식을 돌리지 말고 도구를 쓴다.

```
get_related_articles(record_id, direction="both")
```

반환:

- `outbound` — 이 조문이 인용하는 조문. `resolved: true`면 `article`에 본문까지 들어 있다
- `inbound` — **이 조문을 인용하는** 조문들. 여럿이 같은 조문을 지목하면 그게 중심 조문이다
- `unresolved` — 해소하지 못한 참조. `kind: "external_law"`는 국가 법령이라 이 코퍼스 밖이다.
  **이 목록을 무시하지 않는다.** 답변에 "이 조문은 고등교육법시행령을 인용한다"고 밝힐 근거다

`kind` 5종:

| kind | 뜻 | 답변에서 할 일 |
|---|---|---|
| `cross_rule` | 코퍼스 안 다른 규정 | 해소된 조문을 함께 제시 |
| `same_rule` | 같은 규정 안 조문 | 같이 인용 |
| `external_law` | 국가 법령 등 코퍼스 밖 | **조문 내용을 지어내지 않는다.** 법령명을 밝히고 국가법령정보센터 확인을 안내 |
| `external_law_unmatched` | 법령·외부 규정으로 보이나 사전 미등재 | 위와 같게 다루되 "확인 필요" 표현을 쓴다 |
| `attachment_not_collected` | 별표·서식 위임 | §7-A "규정에 없는 부분"과 **구별해** 미수집으로 밝힌다 (`reason_code` 참조) |

`reason_code`: `image_only`(정본이 이미지로 제공) / `parser_scope`(원문에는 있으나 수집 범위 밖).
어느 쪽이든 내용을 추정해 채우지 않는다.

실측: 농생명산업대학원 교학규정 제11조의2 → 학칙 제30조 해소.
학칙 제30조의 `inbound`는 4건(농생명·글로컬미래전략·산업·정책 대학원 교학규정).

### D. 편제 구조로 인접 조문 훑기 — 보조 경로

모든 레코드에 `장`·`절` 필드가 있다(해당 없으면 `null`). 같은 절에 묶인 조문은
같은 주제를 다루므로, 근거 조문을 하나 찾으면 그 `절` 값으로 이웃을 훑을 수 있다.

**한계를 반드시 알아둔다 — 관련 조문이 인접해 있다는 보장이 없다.**
학칙은 **재입학을 제30조(입학 관련 장)에**, 복학·퇴학·제적을 **제35~37조(학적변동 장)에** 둔다.
제35~38조만 훑으면 제30조에 영원히 닿지 못한다. 실제로 이 함정 때문에 오답이 나온 적이 있다.

따라서 §5-D는 §5-C(상호참조)를 대체하지 못한다. **항상 C를 먼저 하고 D를 보조로 쓴다.**

## 6. 부존재 판정 프로토콜 (가장 위험한 지점)

"근거가 없다"는 말은 답변에서 가장 강한 주장이다. 있는 조문을 없다고 하면
사용자는 존재하는 권리를 포기하게 된다. 실제로 그런 오답이 발생한 적이 있다.

### A. 부존재 선언 최소 요건

**아래를 거치기 전에는 "없다"·"확인되지 않는다"를 쓰지 않는다.**

1. **`hints` 확인** — `query_terms_unmatched`가 비어 있으면 어휘는 코퍼스에 있다는 뜻이다.
   즉 **검색 방식의 문제**이지 부존재가 아니다. 질의어를 규정 용어로 바꿔 다시 친다.
2. **상호참조 추적** — 검색된 조문에 대해 `get_related_articles`를 돌렸는가. (§5-C)
3. **상위 규정 직접 조회** — 학칙·교학규정 등 상위 규정에 대해 `get_article`을 시도했는가.
   `제○조의2` 형태도 확인했는가.

셋 중 하나라도 건너뛴 상태라면, 부존재를 언급하지 말고 **탐색을 계속한다.**
그래도 답을 내야 하는 상황이면 "현재까지 확인하지 못했다"고만 쓰고
**어디까지 확인했는지 경로를 밝힌다.**

### B. 표현 규칙

- 코퍼스에서 못 찾은 것 → **"확인되지 않습니다"** (사실 진술)
- 조문이 존재하지 않는다는 단정 → **쓰지 않는다** (검증 불가능한 주장)

수집 범위 밖인 것과 실제 부존재를 코퍼스만으로 구별할 수 없다.
이 구별 불가능성을 사용자에게 숨기지 않는다.

## 6-2. AI 관련 문의

**작성 시점 코퍼스에 생성형 AI·인공지능을 직접 규율하는 조문이 확인되지 않는다.**
다만 이것은 **관측 결과이지 전제가 아니다.** 매번 확인한다.
코퍼스가 갱신되어 조문이 생겼는데 이 절만 믿고 "없다"고 답하면 그 자체가 오답이다.

판정은 `hints`로 한다.

```
search_rule("생성형 인공지능 챗봇")
→ count: 0, hints.query_terms_unmatched: ["생성형", "챗봇"], suggest: "no_such_concept"
```

⚠️ **`인공지능`은 이제 코퍼스에 있는 어휘다.** 규정 계층 확장으로
`전남대학교 인공지능융합연구소 규정`·`사무분장 규정` 등이 들어왔기 때문이다.
따라서 `search_rule("인공지능")`은 결과를 반환하고 `hints`도 붙지 않는다.

**그러나 그것은 AI 활용을 규율하는 조문이 아니다.** 연구소 설치·조직·사무분장 규정이다.
이걸 "AI 활용 근거"로 붙이면 정확히 가짜 근거다. 어휘 매칭과 규율 대상은 다르다.

판정 순서:

1. `query_terms_unmatched`에 `생성형`·`챗봇`처럼 어휘가 아예 없으면 → 개념 부재
2. 어휘는 매칭됐어도 **조문제목·본문이 연구소 설치·조직·사무분장이면 → AI 활용 근거 아님**
3. 둘 중 어느 쪽이든:

1. **근거 조문 확인되지 않음**으로 처리한다.
2. 인접 조문(표절 정의, 원격수업 콘텐츠, 정보보안 등)은 **"직접 근거는 아니지만 관련될 수
   있는 일반 규범"** 으로 별도 절에 분리하고, 적용 여부를 단정하지 않는다.
3. 실무 안내는 규정이 아니라 **담당 부서·교과목 운영 재량**임을 명시한다.

반대로 `query_terms_unmatched`가 비어 있는데 결과가 빈약하면 어휘는 있다는 뜻이므로,
§6-A대로 탐색을 계속한다.

문제는 **검색이 실패하지 않는다는 점**이다. 그럴듯한 인접 조문이 고득점으로 올라온다.
이것을 근거로 붙이면 존재하지 않는 규정을 만들어낸 것과 같다. **가짜 근거(false grounding)** 라 부른다.

근거로 **쓰면 안 되는** 대표 오탐:

| 조문 | 실제 규율 대상 |
|---|---|
| 연구윤리진실성위원회 규정 제4조 | 연구자의 연구부정행위 정의. 학부 과제 규범이 아니다 |
| 원격수업 운영 지침 제11조 ② | 외부 제작 콘텐츠의 보조자료 사용. 제정 시점 규율 대상이 AI였다고 볼 근거 없음 |
| 정보보안기본지침 제14조 | 정보화사업 발주 시 용역업체 대상. 교원 일상 도구 사용이 아니다 |
| 연구비 중앙관리지침 제50조 | "활용"이 연구성과 관리를 뜻함 |

> AI 활용 범위는 현재 학칙·규정 차원이 아니라 **교과목 담당 교원의 강의계획서**에서
> 정해지는 것이 일반적이다. 이 사실 자체는 규정 근거가 아니므로 단정하지 말고,
> 확인 경로(정보화본부·교무과·학사과)로 안내한다.

## 7. 답변 템플릿

### A. 근거 조문을 찾은 경우

```markdown
**답변**
(결론 2~3문장. 조문에서 직접 따라나오는 내용만.)

**근거 조문**
{규정명} {조문번호}({조문제목}) {해당 항}

> {본문 원문 그대로}

**출처**
- 판본 ID: `{record_id}`
- 수집일시: {수집일시}
- 원문: {source_url}

**규정에 없는 부분**
(질의 중 조문으로 답할 수 없는 항목을 명시. 없으면 이 절을 생략한다.)
확인 경로: {소관 부서}
```

`record_id`와 `수집일시`를 빼지 않는다. 이게 없으면 나중에 검증이 불가능하다.
구판본을 인용해야 할 때는 출처 절에 `현행 여부: 구판본(is_current=false)` 줄을 추가한다.

### B. 찾지 못한 경우

```markdown
**근거 조문을 찾지 못했습니다.**

사용한 질의어: `{질의어1}`, `{질의어2}`
결과: {not_found / 검색은 되었으나 관련성 심사에서 전부 탈락}
{hints가 있으면: 코퍼스 어휘에 없는 질의어: `{query_terms_unmatched}`}

추정 답변은 제공하지 않습니다.

확인 경로: {학사과 / 교무과 / 해당 소관 부서}
{탈락시킨 조문이 있으면: 참고로 아래 조문이 검색되었으나 주제가 달라 근거로 쓰지 않았습니다. — 목록}
```

**탈락 사유를 밝히는 것이 중요하다.** 사용자가 "왜 못 찾았는가"를 알아야 다음 행동을 정할 수 있다.

### C. 부분적으로 찾은 경우

A 템플릿을 쓰되 **"규정에 없는 부분"** 절을 반드시 채운다.
찾은 부분의 확실함이 못 찾은 부분까지 덮지 않도록, 두 영역의 경계를 문장으로 명시한다.

## 8. 응답 전 체크리스트

- [ ] 인용한 조문을 `search_rule` 또는 `get_article`이 실제로 반환했는가
- [ ] `record_id`와 `수집일시`를 적었는가
- [ ] `get_related_articles`로 상호참조를 확인했는가 (§5-C)
- [ ] `unresolved`에 외부 법령 참조가 있으면 답변에 밝혔는가
- [ ] `is_current: false` 구판본을 그렇다고 밝히지 않은 채 인용하지 않았는가
- [ ] `is_repealed: true` 폐지 조문을 근거로 쓰지 않았는가
- [ ] `matched_terms`에 질의 핵심어가 실제로 있는가 (부수어만 매칭된 것은 아닌가)
- [ ] 부설고등학교학칙 등 차단 대상을 근거로 쓰지 않았는가
- [ ] 대학원생 문의라면 해당 대학원의 교학규정을 확인했는가
- [ ] **"없다"고 쓰기 전에 §6-A 요건을 모두 거쳤는가** (`hints` 확인 포함)
- [ ] 부존재를 "없다"가 아니라 "확인되지 않는다"로 썼는가
- [ ] AI 관련 문의라면 §6-2를 적용했는가 (`query_terms_unmatched` 근거)
- [ ] 대학원 재입학 문의라면 **학점 통산 문언의 재량/기속 차이**를 확인했는가 (corpus-map §2-2)
- [ ] `text_integrity`가 붙은 조문을 인용했다면, 원문대로 옮기고 손상 사실을 밝혔는가 (§5-A-2)
- [ ] `각호1` 같은 옛 표기를 '오타'로 보고 임의로 고쳐 쓰지 않았는가 (§5-A-2)
- [ ] `repealed_clauses`·`repealed_items`에 있는 항·호를 근거로 인용하지 않았는가
- [ ] `external_law`/`external_law_unmatched` 참조의 내용을 지어내지 않았는가
- [ ] `unresolved`에 `attachment_not_collected`(별표 미수집)가 있으면 '규정에 없음'과 구별해 밝혔는가
- [ ] 조문에 없는 절차·기한·창구를 임의로 덧붙이지 않았는가
- [ ] 못 찾은 부분을 "못 찾았다"고 썼는가 (얼버무리지 않았는가)
