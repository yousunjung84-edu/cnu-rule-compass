## 2. 도구 계약 변경 (하위 호환)

기존 3개 도구는 시그니처·필드 유지. **추가만** 있었다.

### 파라미터 추가
```
search_rule(query, k=5, include_superseded=False, include_repealed=False)
```
⚠️ **기본 동작이 바뀐다**: 구판본·삭제 조문이 기본 결과에서 빠진다(그게 목적).
감사 대응처럼 당시 판본이 필요하면 `include_superseded=True`로 켠다.

### 응답 필드 추가
- `장`, `절` — 해당 조문이 속한 편제 구조 (없으면 `null`). "같은 절의 다른 조문" 탐색에 쓸 수 있다
- `is_current`, `superseded_by`, `is_repealed`, `repealed_date`
- `hints` — 결과가 0~1건일 때만 붙는다 (`query_terms_unmatched`, `suggest`, `note`)

### 신규 도구
```
get_related_articles(record_id, direction="outbound"|"inbound"|"both", resolve=True)
list_rules(division=None, include_superseded=False)
get_corpus_stats()
```

`record_id` 형식·값은 보존했다. 본문 수정 전에 기존 파생 ID를 코퍼스에 동결했으므로
이미 발급된 답변의 인용(`rule-2200000155895-6ef5c792ea6d7b66` 등)은 그대로 유효하다.

## 3. 남은 한계 — 스킬에 그대로 유지할 것

**동의어 확장은 하지 않았다.** 핸드오프 §T2 회귀 케이스 중
`"성적 이의신청 언제까지" → 교학규정 제46조`는 달성하지 못했다. 코퍼스가 해당 개념을
`정정`으로 표현하고 제46조 본문에 `이의신청`이 없어서, 검색 게이트가 아니라 어휘의 문제다.
사용자 표현과 규정 용어가 다를 수 있다는 안내는 스킬에 남겨 두는 편이 좋다.

## 4. 검증 방법

```python
search_rule("재입학", k=10)          # 학칙 제30조 포함
search_rule("재입학 허가 신청")        # 학칙 제30조 + 교학규정 제11조, 교학규정 제10조 없음
search_rule("생성형 인공지능 챗봇")     # count 0 + hints.query_terms_unmatched
get_related_articles("rule-2200000155895-6ef5c792ea6d7b66", direction="inbound")  # 4건
get_corpus_stats()                   # 조문_수 == 색인_문서_수, warning 없음
```

# v1.6.0 / 스킬 v1.5.0 — 핸드오프 v1.5(T27~T32) 반영 (2026-08-11)

## 1. 이번 회차의 교훈 — 기능 추가가 다른 기능을 오염시킨다

T22(별표 수집)는 명세대로 구현됐고 자체 결함이 없었다. 그런데 별표 본문이 조문의
수십 배라, 검색 응답에 섞이는 순간 **전 도메인의 답변 품질을 떨어뜨렸다.**
`계약 체결 수의계약 금액 기준` 질의 응답 28,148자 중 27,829자(98.9%)가 별표였고,
그 별표들은 질의와 무관한 연구비 집행 기준이었다.

→ 새 `record_type`을 도입할 때는 **검색 응답에서의 노출 방식을 함께 설계한다.**

## 2. 반영 내용

| 항목 | 조치 |
|---|---|
| T27 (P0) | `search_rule`이 별표를 기본 제외. `attachments_omitted`·`attachments`로 제외 사실 명시. `include_attachments=true`면 포함하되 본문 200자 절단 + `표_수`·`행_수`·`본문_길이` |
| T28 | 별표 조문제목을 원문(목차 줄·본문 첫 줄·표 머리셀)에서 추출해 채움. 위임 조문(`제22조 ③항의 관련`)을 `위임조문` 필드로 기록 |

## 3. 명세와 다르게 처리한 것

**T28 "전 코퍼스 조문제목 == '' 0건"은 달성하지 않았다.** 남은 20건은
삭제 조문 19건(`<삭제>`, `삭제 <2016. 2. 1.>`)과 부칙 시행일 조항 1건인데,
**원문에 제목이 없다**(정본 응답·kordoc 마크다운 양쪽 대조 확인).
채우면 날조이므로 비운 채로 두고 회귀 테스트로 그 사실을 고정했다.

**T30의 가설은 관측과 달랐다.** "총무과에 계약 규정이 없다 = 수집 누락"이 전제였으나,
게시 목록(2026-07-24) 총무과 10건에도 계약 규정이 없다. 계약·회계는 규정 계층의
「전남대학교 재정 및 회계의 운영에 관한 규정」과 국가계약법령 소관이다. 수집 누락이 아니다.

## 4. 부수로 드러난 것 — T22 수집 자체의 공백

별표 헤더 패턴이 `[별표]`만 있는 줄만 인정해, **제목이 같은 줄에 붙은 형태와
`<별표 1>` 형태를 통째로 놓치고 있었다.** 86건 추가 편입(32 → 118).
이해충돌지침 별표 1(법 위반행위 징계양정기준), 장학지침 별표 1~5(장학금 종류),
수업관리 지침 별표(성적 환산표) 등 **판단 기준이 별표에만 있는 것들**이다.
별표 참조 해소도 44 → 134건.

## 3. 확장이 드러낸 결함 3건

**(1) 구판본 판정 실패 — 74개 규정 1,263조문.** 개정 때 규정명이 바뀌면
('환경관리원 취업규칙' → '환경관리직 취업규칙') 같은 이름의 현행본이 없어
구판본 판정이 실패했다. 구판본이 현행으로 잡히면 **폐지된 기준을 근거로 답하게 된다.**
→ 대응 현행본을 못 찾아도 규정명 꼬리 괄호에 연도가 있으면 구판본으로 본다.
연도 없는 '… 학과 신설·폐지 및 학사구조 개편 지침'은 주제어일 뿐이므로 현행 유지.

**(2) 별표 라벨 폭주 10건.** 원문의 여는·닫는 괄호가 어긋나면(`## [별표 1〕`)
라벨이 다음 `>`까지 삼켜 `별표 2〕 ### … <table` 같은 인용 불가 조문번호가 생겼다.
→ 닫는 괄호 후보 확대 + 라벨 20자 제한.

**(3) 제목 없는 부칙 폐지 조문.** '이 지침 시행과 동시에 종전의 지침은 폐지한다'가
제목이 없어 본칙으로 분류됐다. → 제목 없이 본문 문구만으로도 부칙으로 본다.

## 4. 운영 영향 — 메모리

인덱스 메모리가 **1.4GB**로 늘어 Cloud Run 512Mi로는 기동하지 않는다.
`--memory=2Gi --cpu=2`로 올렸다. 인덱스 빌드 7.6초(콜드스타트에 그대로 더해진다),
검색 자체는 2ms. 8/18 행사 전 `min-instances=1` 재점등이 더 중요해졌다.

## 5. 남은 것

미수집 122건은 전부 `제N조 패턴을 찾지 못함` — **조문 구조가 없는 항목식 문서**다
(`1. 목적 / 2. 관련 규정 / 3. 용어 정의`). 예: 전남대학교 교직과정 운영 지침,
교원승진임용 소요연구업적 평가방법 개선지침. 내용은 실재하고 실무 질의에 답이 되지만
코퍼스의 레코드 단위가 조문이라 담으려면 새 record_type이 필요하다 —
`list_articles`·인용 형식의 의미가 바뀌므로 **박사님 결정 사항으로 남긴다.**

본칙 조문 2건이 적재 상한(30,000자)에 걸려 제외된다(방사선안전관리지침 부칙 제1조,
현장실습지침 제17조). 파서가 뒤따르는 별표를 마지막 조문 본문에 삼킨 결과다.
