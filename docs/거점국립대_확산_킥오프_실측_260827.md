# 거점국립대 규정 MCP 확산 — 킥오프 실측 (2026-08-27)

박사 결정: **표준 제작 + 파일럿 2~3개교 직접 구축** (9개 전부 직접 구축은 보류 —
운영 단일 장애점·졸업 목표와의 충돌 논의 결과). 니즈 출처: 교무과장
(9개 거점국립대 동일 방식 + korea-law 연계 구상).

## 1. 핵심 가정 실측 — "각 학교마다 공개데이터가 있을 것"

**절반만 참이었다.** 규정 계층은 law.go.kr 학칙공포 서비스 공통이지만,
참여 규모가 대학마다 크게 다르다 (korean-law MCP `search_decisions
domain="school"` 실측, 2026-08-27):

| 대학 | 학칙공포 게시 건수 | 판정 |
|---|---|---|
| 경북대 | **446** (운영지침급까지 게시) | 파일럿 1순위 — 한 소스로 지침 계층까지 |
| 서울대 | 405 (영문 규정 포함) | 상 |
| 경상국립대 | 331 (통합 특례규정 존재) | 상 — 대학 통합 이력 문서화 사례 |
| 충북대 | 218 | 중 |
| 부산대 | 209 | 중 |
| 충남대 | 186 | 중 |
| 강원대 | 186 | 중 |
| 제주대 | **29** | 부분 참여 — 자체 게시판 의존 추정 |
| 전북대 | **0** | 미참여 — 자체 규정집만, 최난도 |
| (전남대) | 281 + 지침 633(자체 게시판) | 기준점 |

- 목록 API: 공개 `lawSearch.do`는 도메인 등록 검증에 막히지만, **korean-law
  MCP(법제처 등록 키)로 목록·전문 모두 조회 가능** — 수집 경로 확보됨
- 개별 문서는 기존 수집기(lawService.do) 패턴 그대로 재사용 가능

## 2. 함의

1. **"동일한 방식"은 규정 계층에서 성립한다.** 수집기 1개로 9개 대학 커버.
2. **지침 계층이 대학별 변수다.** 경북대형(학칙공포에 다 올림)이면 공짜,
   전남대형(자체 게시판 HWP)이면 대학별 파서, 전북대형(학칙공포 0)이면
   자체 게시판이 전부 — 파일럿에서 이 세 유형을 하나씩 밟아야 표준이 완성된다.
3. 제주·전북은 "수집률 분모 공개" 원칙(T30)이 더 중요해진다 — 적은 코퍼스로
   서비스하면 "없다" 오답 위험이 커지므로 수집 범위 고지가 필수.

## 3. 파일럿 후보 제안

| 순서 | 대학 | 이유 |
|---|---|---|
| 1 | **경북대** | 최다 게시 + 지침급 포함 → 최소 비용으로 전 파이프라인 검증 |
| 2 | **부산대 또는 충북대** | 중간 규모 — 자체 게시판 보완 수집(전남대형) 일반화 검증 |
| 3 | (선택) **전북대** | 최난도 유형 — 표준의 한계를 정의하는 케이스 |

## 4. 표준화 대상 (전남대에서 이미 검증된 자산)

- 수집: collect_regulations(규정)·collect_guidelines(지침)·별표·항목식 파서
- 판정: 현행/구판본 4규칙(괄호 꼬리·연도 접두·중복 key·개명 대사)
- 품질: 재현 테스트 선행 게이트·골든 케이스·축 검증 방법론
- 소비: advisories(응답 신호)·부서 에이전트 템플릿(§A~C 공통 + §D 문맥)
- 운영: 월간 갱신 잡(대사→수집→검증→리포트)·수집률 분모 공개
- **korea-law 연계(신규)**: external_law 참조를 korean-law MCP로 핸드오프 —
  교내 규정 → 국가 법령 근거 사슬 연결. 설계 필요.

## 5. 다음 단계 (착수 시)

1. 표준 레포 분리 설계 — 전남대 하드코딩(호스트·편제) 제거, 대학 프로필화
2. 경북대 파일럿: korean-law MCP 경유 목록 → 수집 → 검증 게이트 → 배포
3. korea-law 핸드오프 설계 (unresolved.external_law → search_law 브리지)
4. 거버넌스 문서: 운영 주체·비용·공식 등록 경로(대학별 AIONI 상당 채널)

⚠️ 미확정: 프로젝트의 주체·예산 틀(교무과장 구상의 실체), 각 대학 공식 채널
등록 경로. 개인 프로젝트로 시작하되 이 두 가지가 확산 단계의 게이트다.
